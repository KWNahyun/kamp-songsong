# 제공 YOLOv3 노트북 검토 및 기준 모델·데이터 방향

검토일: 2026-09-29. 소스와 저장 출력을 읽었으며 실행·학습하지 않았다.

## 결론

두 비교 기준은 D-FINE과 YOLO로 정한다. 시작 구성은 D-FINE-S와 YOLOv8s를 제안한다. YOLOv8은 널리 채택된 구현이라는 [공식 소개](https://docs.ultralytics.com/models/yolov8/)를 근거로 선택하며, 최신 버전이나 인기도 1위라고 주장하지 않는다. 주 실험은 KAMP의 주 500장으로 설계하고 외부 데이터는 선택적인 실행 점검 자료로 남긴다.

공식 평가 문구는 **베이스라인 포함 2개 이상 모델 비교**다. 동일 입력·분할·평가에서 두 계열을 비교하고, 구조 변경 효과는 해당 모델 내부 ablation으로 분리한다. 모델 크기 이름 S가 같아도 연산량이 같지는 않다.

## 실제 코드 흐름

대상: [노트북](<../../../data/raw/4.%20X-ray%20검사장비%20AI%20데이터셋/dataset/yolov3_20201200.ipynb>). 아래 셀 번호는 0부터 시작한다.

1. Windows C: 경로와 Python 3.7/PyTorch 1.7 계열 환경 설치 안내.
2. 장비별 BMP를 복사·정리하고 OpenLabeling으로 사각형 정답 작성. TXT를 images와 대응하는 labels에 배치.
3. 이미지 파일을 약 80/20으로 임의 분할해 train.txt/test.txt 작성.
4. custom.data와 yolov3-spp.cfg의 단일 defect 클래스로 YOLOv3-SPP 학습.
5. last.pt로 이미지에 예측 박스를 그리고 test.py로 평가.

학습 셀 42는 epochs=15, batch-size=3, weights/last.pt, CPU, --nosave다. 주석에 적힌 150 epochs/batch 5와 다르다. train.py에서 --nosave는 마지막 checkpoint만 저장한다는 의미다. weights/last.pt의 학습 출처와 시험 이미지 노출 이력은 이 호출만으로 확인할 수 없다. 새 비교에서는 출처가 확인된 초기 가중치를 사용한다.

| 날짜/장비/중복 그룹 통제 없음 | 셀 28 및 splitdata.py | 근접 촬영과 원본 파생본이 양쪽에 섞일 가능성을 통제하지 않는다. |

저장된 평가 출력은 100장·234 target에 P/R/mAP50/F1이 모두 0이다. 하지만 명령에는 CPU가 있고 저장 출력에는 RTX 3080이 등장하며 GPU–PyTorch 비호환 경고도 있다. **저장된 코드와 출력이 같은 실행 상태인지 확정할 수 없고, 이 수치를 검증된 대회 기준 성능으로 인용하면 안 된다.** 이를 GPU 경고 하나가 원인이라고 단정할 근거도 없다.

## 500장을 사용하는 방향

500개의 주 TXT와 정확히 대응하는 원본 이미지 한 벌을 사용한다. 누적 images 15/50/100/200/300/400 묶음을 더하면 중복이 생긴다. 주 라벨은 단일 클래스·1,147 bbox이며, 보조 TXT와 섞지 않고 버전을 고정한다.

분할 비율은 약 70/15/15를 출발점으로 삼을 수 있으나, 350/75/75를 맞추기 위해 같은 촬영군을 자르지 않는다. 날짜 단위 그룹 분리와 중복·근접 촬영 검토를 우선하고 장비/크기/객체 수 분포를 공개한다. 제품 ID가 없어 날짜 그룹만으로 모든 반복 제품 누수를 제거했다고 보장할 수는 없다. 아직 분할 파일을 생성하지 않았다.

팀원이 전처리한 뒤 이미지가 바뀌어도 같은 원본 ID는 같은 split을 유지한다. val은 모델·임계값 선정, test는 고정한 선택의 최종 평가에 사용한다. 두 모델에는 같은 라벨·처리 버전·입력 기하 변환·평가 코드를 적용한다. 계열 비교는 학습 recipe와 튜닝 예산 차이를 공개하고, 모듈 ablation은 recipe를 고정한다.

원본 RGB는 표시 의존을 확인하는 진단 실험으로는 쓸 수 있지만, 그 성능을 이물 검출 능력의 주 결과로 삼지 않는다. 회색조 변환만으로 표시 윤곽이 없어지는 것도 아니다. 팀원의 첫 고정 처리본으로 본 실험을 시작하는 것이 목적에 가장 직접적이다.

500장은 모두 이물 라벨이 있으므로 객체 recall/AP와 양성 영상의 FP는 평가할 수 있다. 정상 오경보율·안전한 자동 통과·실제 운영 재검사율을 검증하는 정상 표본은 별도 문제다.

외부 닭고기 데이터는 구현·입출력·음성 영상 평가 절차 점검에 남겨 둔다. 그 데이터에서 최적 모듈이나 임계값을 골랐다고 KAMP에서 최적이라고 볼 수 없다. 주 실험을 위해 외부 데이터 사용을 계속할 필요는 없다.

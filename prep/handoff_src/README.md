# KAMP X-ray 이물 탐지 — 학습·평가용 데이터 패키지 (분할 v2)

모델 실험에 필요한 **데이터, 고정된 train/val/test 분할, 공통 평가 도구**가 들어 있습니다.
모든 모델을 **같은 분할, 같은 지표**로 비교하기 위한 패키지입니다.

## 1. 구성
```
kamp_xray_v2/
├── images/{train,val,test}/*.png   마커를 지운 X-ray 이미지 (8bit 흑백 PNG, 단채널)
├── labels/{train,val,test}/*.txt   공식 정답 라벨 (YOLO 형식: class cx cy w h, 0~1 정규화, class 0 = defect)
├── split_manifest.csv              이미지별 split 과 그 근거 (장비, 날짜, 묶음, 세션)
├── data.yaml                       YOLO(ultralytics)용 설정
├── coco/instances_{train,val,test}.json   COCO 형식 (bbox = [x, y, w, h] 픽셀, category 1 = defect)
└── tools/
    ├── verify_split.py             내 train/val/test 목록이 이 분할과 같은지 검사
    └── evaluate.py                 공통 평가 (베이스라인과 같은 지표)
```

## 2. 데이터 요약
| split | 이미지 | 결함 | (장비, 날짜) 묶음 |
|---|---:|---:|---:|
| train | 350 | 797 | 17 |
| val | 66 | 144 | 11 |
| test | 84 | 206 | 9 |

- **장비 3대**(manifest의 `machine`: M1 = 1호기, M2 = 2호기, M3 = 3호기). 해상도가 장비마다 다릅니다: M1 352×332 / 316×332, M2 316×332, M3 576×444
- 원본 이미지에는 장비가 그린 결함 위치 표시(컬러 사각형)가 박혀 있습니다. **이 패키지의 이미지는 그 표시를 인페인팅으로 지운 것**입니다. 표시가 남은 원본은 과제 규칙상 탐지 특징으로 쓸 수 없으므로, 반드시 이 이미지를 쓰세요.
- 라벨은 주최 측 **공식 TXT를 수정 없이** 복사한 것입니다.
- 이미지는 **단채널 PNG**입니다. 3채널 입력이 필요한 프레임워크는 읽을 때 3채널로 복제하면 됩니다(OpenCV `imread` 기본값이 그렇게 동작함).

**데이터 특성 (모델 설계 시 참고)**
- 결함 대부분이 **약 2×2px의 작은 점**입니다. 416 입력으로 줄이면 1.5~2.5px가 되니, 입력 해상도와 작은 객체 성능이 중요합니다.
- 정답 박스는 결함보다 훨씬 크고(한 변 5~21px), 크기가 들쭉날쭉합니다. 그래서 IoU 지표 외에 **중심거리 지표**도 같이 봅니다.
- 모든 결함이 **같은 표준 테스트피스**(띠 끝의 작은 점)입니다. 결함의 크기·위치·모양이 거의 다양하지 않습니다.

## 3. 분할 규칙 — 반드시 이 분할을 그대로 쓰세요
- **분할을 새로 만들지 마세요.** `split_manifest.csv`(또는 이미지 폴더 구조)를 그대로 따르세요.
- 묶음 단위는 **(장비, 날짜)**입니다. 같은 장비가 같은 날 찍은 사진은 모두 한 split에만 있습니다. 같은 테스트피스를 몇 초 간격으로 여러 장, 4시간마다 반복 촬영한 데이터라, 같은 날 사진끼리 비슷해서 나눠 넣으면 평가가 부풀려지기 때문입니다.
- **train**: 학습 / **val**: 모델 선택, 하이퍼파라미터·임계값 조정 / **test**: 모든 결정이 끝난 뒤 **최종 성적에만** 사용
- 조건마다 **seed 3개로 3번 학습**해 평균 ± 표준편차로 보고하세요. seed 간 차이가 AP 0.01~0.02 수준입니다.
- 목록 파일을 따로 만들었다면 검사하세요.
  ```bash
  python tools/verify_split.py --train my_train.txt --val my_val.txt --test my_test.txt
  ```

## 4. 사용법
**YOLO (ultralytics)**: `data.yaml`의 `path`를 이 폴더의 절대 경로로 바꾸고 `data=data.yaml`로 학습합니다. 폴더 구조가 `images/<split>` ↔ `labels/<split>`이라 그대로 인식됩니다.

**COCO 형식 모델** (mmdetection, detectron2, DETR 등): `coco/instances_<split>.json`을 쓰고, 이미지 루트는 이 폴더입니다(`file_name`이 `images/<split>/...` 상대 경로).

## 5. 평가 — 결과를 비교하려면 이 스크립트로
모델마다 평가 코드가 다르면 숫자를 비교할 수 없으니, 예측 결과를 아래 형식의 CSV로 저장해 `tools/evaluate.py`로 계산하세요.

```csv
image_id,x1,y1,x2,y2,conf
001_20200623_003516(8),361.0,190.0,372.0,201.0,0.583
```
- 좌표는 **원본 이미지 픽셀 기준** (x1, y1) 좌상단, (x2, y2) 우하단
- `image_id`는 확장자 없는 파일 이름
- AP를 위해 **낮은 신뢰도 검출까지 모두** 넣으세요 (권장: NMS 후 conf ≥ 0.001)

```bash
python tools/evaluate.py --pred my_test_predictions.csv --split test
```

| 지표 | 의미 |
|---|---|
| AP50 | IoU ≥ 0.5 매칭, 101점 보간 AP |
| P@0.25 / R@0.25 | 신뢰도 0.25 이상 검출 기준 정밀도 / 재현율 |
| ctr_AP50 / ctr_R@0.25 | IoU 대신 **박스 중심 거리 ≤ 8px**로 매칭한 같은 지표 |
| 장비별 | M1 / M2 / M3별 AP50, R@0.25 |

**비교 기준 (베이스라인)**: YOLOv3-SPP, 입력 416, COCO 사전학습 초기화, 300 epoch, 이 패키지와 같은 이미지·분할, seed 3개

| split | AP50 | P@0.25 | R@0.25 | ctr_R@0.25 |
|---|---|---|---|---|
| test | 0.935 ± 0.011 | 0.959 ± 0.003 | 0.945 ± 0.006 | 0.985 ± 0.005 |
| val | 0.951 ± 0.015 | 0.972 ± 0.012 | 0.956 ± 0.008 | 0.981 ± 0.004 |

## 6. 과제 규칙 (주최 측 안내)
- 색상 표시(마커)는 탐지의 직접적인 특징으로 사용 금지 → 이 패키지의 마커 제거 이미지만 사용
- 공식 정답은 TXT 라벨 → `labels/` 그대로 사용
- 외부 데이터(사전학습 가중치 포함)를 쓰면 **활용 사유·방법·출처**를 결과보고서에 명시해야 하며, 공개에 문제없는 데이터만 사용 가능
- GT 없는 이미지(2,020장)는 이 패키지에 없습니다. 필요하면 데이터 담당자에게 요청하세요. val·test와 같은 (장비, 날짜)의 이미지는 쓰면 안 됩니다.
